# Skill vs Runtime：人格模拟方案对比（一页答辩版）

## 目标

回答一个常见质疑：  
“为什么不直接用一个 `.skill` 文件模拟人格？”

## 结论（可直接复述）

`.skill` 适合定义“说话风格与任务规则”；  
当前项目是“可持续演化的人格运行时系统”。  
两者不是替代关系，而是不同层级。  
当目标是长期拟人、可控、可验证时，运行时系统有不可替代优势。

## 核心差异

| 维度 | 仅 `.skill` | 当前项目（运行时系统） |
|---|---|---|
| 人格状态 | 静态文本 | 可持久状态（记忆、关系阶段、分值） |
| 记忆注入 | 手工拼接 | 配置化策略选择（类型配额/权重/衰减/去重） |
| 上下文预算 | 无硬约束，易被挤出 | 分段预算+总预算，关键段保留 |
| 跨会话连续性 | 弱 | 强（落盘并回写） |
| 可观测性 | 弱，难定位漂移原因 | 强（结构化数据可追踪） |
| 可验证性 | 主要靠主观感受 | 有回归测试与指标体系 |
| 工程治理 | 难做灰度与回滚 | 可 A/B、可回放、可回归 |

## 我们的“绝对优势”

1. 状态连续性优势  
人格不依赖单轮提示词，而依赖跨轮状态。关系状态机与记忆系统可持续更新，不会每轮“失忆”。

2. 稳定注入优势  
记忆不是设“最近几条随机进 prompt”，而是可配置筛选策略。`fact/preference` 可被长期稳定保留，降低人漂移。

3. 预算控制优势  
关键人格段（identity/style/relationship）由预算保护，不会被历史对话淹没。这是纯 `.skill` 很难稳定做到的。

4. 可验证优势  
同一输入在同一配置下可复现，能够测量“人格是否变差”，并通过回归测试阻止退化。

5. 生产可治理优势  
可配置、可回滚、可审计，适配多人协作与长期迭代；不是“改几句 prompt 看运气”。

## 指标体系（建议对外展示）

1. 人设漂移率（Persona Drift Rate, PDR）  
定义：与角色核心设定冲突的回复占比。  
目标：越低越好。

2. 事实召回率（Fact Recall Rate, FRR）  
定义：角色核心事实在应当被引用场景中的命中率。  
目标：越高越好。

3. 关系连续性得分（Relationship Continuity Score, RCS）  
定义：相邻会话中关系状态变化是否符合历史轨迹与触发规则。  
目标：越高越好。

4. 关键段保留率（Critical Section Retention, CSR）  
定义：在长上下文下，identity/style/relationship 三段仍被注入的比例。  
目标：越高越好。

5. 回复一致性（Reply Consistency, RC）  
定义：同输入+同状态下多次输出的语气与立场一致程度。  
目标：越高越好。

## 对比实验方案（最小可执行）

1. 方案 A：仅 `.skill`（静态人格文本）  
2. 方案 B：当前运行时系统（记忆策略+预算+关系状态机）
3. 使用同一批 100 条多轮对话脚本，覆盖：闲聊、追问、情绪波动、跨天衔接。
4. 对 PDR/FRR/RCS/CSR/RC 打分并统计均值与方差。

预期结果：  
方案 B 在 PDR、RCS、CSR 上显著优于方案 A；  
方案 A 在短期单轮可接近，但中长会话稳定性明显劣化。

## 建议定位（对外说法）

`.skill` 是“角色说明书”；  
当前项目是“角色操作系统”。  
说明书能定义角色，操作系统才能长期稳定地运行角色。
